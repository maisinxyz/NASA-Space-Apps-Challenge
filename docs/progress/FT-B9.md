# FT-B9 — Farm co-pilot

Date: 2026-11-15.

Mounted `POST /copilot/chat` using Groq `openai/gpt-oss-120b` and its [documented strict JSON schema response](https://console.groq.com/docs/structured-outputs). The API sends no tools, reads `GROQ_API_KEY` from the process environment or the repository root `.env` (environment takes precedence), never returns the key, applies a bounded in-process per-client rate limit, refuses network calls when `OFFLINE=1`, validates message and history limits, and returns sanitized retryable 503 errors on provider failures. Each API process has its own rate-limit state; a shared limiter is required for a multi-worker deployment. Start normally with the root `.env` present or export the key in the API process environment; do not commit the file.

The server rebuilds the demo forecast from the checked-in UBC/KPU request and requested scenario, then supplies the selected field/strategy/year metrics, units, basis, ranges, uncertainty and selected flag to the model. The contract's snapshot does not contain a forecast request hash, crop pool, edits, or climate source, so it cannot identify arbitrary custom or previously edited forecasts. Every answer explicitly discloses that it uses reconstructed demo data that may differ from the screen; unknown selections are reported unavailable. Month data is currently unavailable to this route; `monthly_context` is the narrow B7 integration point. The endpoint does not claim to reproduce the exact screen until a request identity is carried by the contract and client.

Prompt rules prohibit planting orders and income/fertilizer figures, require local checks and data-grounded explanations, and treat user history as untrusted. Structured output enforces response shape, not factual accuracy or adherence to those prompt rules; replies remain probabilistic and require user judgment.
