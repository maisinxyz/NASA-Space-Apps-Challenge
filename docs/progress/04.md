# Prompt 04 — JSON and SSE fixtures

**Branch:** `be/BE-00-fixtures-json`, stacked on `be/BE-00-fixtures-terrain`.

## What was built
- `scripts/make_fixtures_json.py` is deterministic and runs as the second step of `make fixtures`. It reads the Prompt 03 frame and risk files, so metrics, evidence numbers and diff stats come from the binary fixtures.
- Fixtures under `packages/contracts/fixtures/`:

- `packages/contracts/fixtures_lib/contract.py`: `validate_response(instance, path, method, status)` and `validate_schema(instance, name)` use jsonschema 2020-12 against `openapi.yaml`, with format checks. Prompt 05's API tests reuse it.
- `packages/contracts/tests/test_fixtures_valid.py`:
  - Every JSON fixture is mapped to a response schema, and an unmapped fixture fails the test.
  - Errors, both SSE streams and stage order are checked.
  - Cover rotations show lower runoff and erosion than existing.
  - Evidence numbers match the metrics.
  - Anchors fall inside the bbox.
  - Mock labels are present.
  - A negative test checks the validator rejects bad data.

## Notes and gaps
- A rotation `sequence` can list **two crops in the same year** (main crop then cover crop, as in `rot_cover`). The contract allows this. The team should confirm it's the intended reading.
- Storm dates are placeholders, and the labels say "(mock)". They don't claim to be real events.
- Added the `rfc3339-validator` dependency. Without it jsonschema silently skips `date-time` checks. The negative test caught this.
- No fixtures for `/health` (computed), `/notes` (stateful), or the `POST /simulations` body (the API returns `status.json`).
