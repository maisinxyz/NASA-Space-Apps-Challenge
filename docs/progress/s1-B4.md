# s1-B4: Land Scan flow

## Built
- `/scan`: lat/lon (decimal degrees), optional name, optional 0-6 JPG/PNG/WEBP photos. Client validation in `lib/scanForm.ts` mirrors `ScanCreateForm` (lat -90..90, lon -180..180, maxItems 6, name maxLength 120).
- `startScan` then `subscribeScanEvents`: all ProgressStage steps in contract order with done/now/stopped/todo shown by symbol + sr-only text, live server message (aria-live), progress bar.
- `failed` stage or transport error: ErrorCard (message, hint, code) with Try again (same inputs), Edit the location, Use a pre-built site.
- `ready`: sets store `terrainId`, navigates to `/viewer?terrain=<id>`.
- Mock mode: a dev checkbox replays the fixture failure (`mockScenario: "fail"`).

## Files
apps/web/app/scan/page.tsx, lib/scanForm.ts, lib/scanForm.test.ts

## Gaps
- No map pin picker (by instruction). `bbox` (optional in contract) not exposed.
- No file-size check: the contract sets no limit; API's FILE_TOO_LARGE is shown via ErrorCard.
- Progress `pct` is shown as "%" without a basis chip (job progress, not a data value).
