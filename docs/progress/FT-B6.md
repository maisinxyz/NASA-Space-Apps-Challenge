# FT-B6 — KPU soil and demo forecast regression

Date: 2026-11-15.

The KPU 503 was not a loader mismatch: `soil.json` records a SoilGrids point query whose means are null at all three requested depths, and its `summary` is correctly null. The feature table retains that result. The original KPU point query and a full multi-property nearby REST query timed out during this work; a nearby REST single-layer query succeeded. Rather than fabricate soil data, the forecast now uses a separately recorded nearby SoilGrids WCS mapped-cell proxy for fields without a supplied soil test. The WCS output sample at 49.109, -122.639 is approximately 470 m from the configured KPU site point. The proxy is not a measurement of any field, and the current configured site point is not necessarily a field centroid.

`data/seed/site_kpu_langley/soil_nearby_proxy.json` contains the underlying mapped values and depth-weighted summary; its sidecar records source, licence, retrieval date, resolution and processing. ISRIC documents the [SoilGrids WCS](https://dev-docs.isric.containers.wur.nl/globaldata/soilgrids/wcs.html) and [CC BY 4.0 access](https://dev-docs.isric.containers.wur.nl/globaldata/soilgrids/SoilGrids_faqs_02.html). The output is `limited_data`, includes an explicit proxy assumption and per-strategy review flag, and affected field and farm strategy modeled/derived numbers are marked assumed. A supplied field soil test takes precedence. This proxy still needs local soil-test validation and is not represented as the original SoilGrids point.

Verification: offline regression sends both real demo request bodies to the forecast service; every field returns three strategies and KPU reports the proxy and limited-data state. `uv run pytest tests/test_forecast_service.py -q`: 7 passed. `uv run --project services/api pytest services/api/tests -q`: 266 passed, one dependency deprecation warning. The full suite ran with concurrent B1 sidecar changes present in the shared checkout.
