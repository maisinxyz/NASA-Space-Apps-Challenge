## Decisions (REVIEW BEFORE FREEZE)
Everything below is my choice where the PRD was loose or silent. Object to any of them before the freeze.

**General**
1. **No auth:** root `security: []`.
2. **ID patterns:** `^<prefix>_[A-Za-z0-9_-]+$` with prefixes `site_ terr_ scan_ storm_ crop_ rot_ sim_ ins_ note_`. The `note_` and `ins_` prefixes come from examples or are new.
3. **Grid orientation:** all rasters are row-major, row 0 = north, col 0 = west.
4. **HTTP status per error code:** INVALID_INPUT 422, UNSUPPORTED_FILE 415, FILE_TOO_LARGE 413, TERRAIN_COVERAGE_MISSING 422, DATA_SOURCE_UNAVAILABLE 503, WEATHER_UNAVAILABLE 503, SIMULATION_TIMEOUT 504, NOT_FOUND 404, INTERNAL 500. In `Error`, `hint` is optional and `retryable` is required.
5. **Basis:** `Basis` = measured|derived|modeled|assumed. `BasisOrRelative` adds `relative` and is used only in `Metrics.basis` and `DiffStats.basis`.

**Health**
6. `{status: "ok", mode: "offline"|"live", version}`. `version` is the contract version.

**TerrainPackage**
7. `site_id` is nullable (null for user scans). `elevation.model` enum is `DTM | DSM`.
8. `quality_flags` is an **open string set**, not an enum. Known values: `coarse_elevation`, `dsm_includes_vegetation`, `texture_alignment_assumed`, `low_resolution_texture` (from BE-02).
9. `assets.layers` has exactly the 4 PRD layers. `LayerName` enum = `slope | flow_accumulation | depressions | cover_class`, and it constrains `/layers/{name}.png`.
10. Normal map encoding: RGB, `n = byte/255*2-1`, R = east, G = north, B = up.

**Layer catalog** (`GET /terrain/{id}/layers`)
11. `{terrain_id, layers: LayerLegend[]}`. `LayerLegend` = `name, title, kind (continuous|categorical), unit, value_range [min,max], color_ramp (free-text hint), nodata_value (255), classes? [{value,label,color?}], url, basis`.
12. **255 = nodata in every 8-bit layer**. Continuous layers map bytes 0–254 linearly onto `value_range`. Back-end: this sets how you write slope, flow accumulation, and depression PNGs.

**Provenance** (`GET /terrain/{id}/provenance`)
13. `{terrain_id, datasets[], texture?, quality_flags[], assumptions[{statement, basis}], limitations[]}`. `datasets[]` are `Source` plus optional `attribution` and `date_range` (from FE-08's datasets table).

**Weather summary** (`GET /weather/summary?lat&lon`)
14. `{lat, lon, period{start,end}, source{name,resolution_km,basis}, cached, series: TrendSeries[]}`.
15. `TrendSeries` = `id, label, unit, points[{year,value}], trend{method:"theil_sen", slope_per_decade, ci_low, ci_high, ci_level}, summary, basis`. Series are **annual only**. `id` is an open string; suggested ids are `annual_precip_mm`, `heavy_rain_days`, `temp_mean_c`, `root_zone_wetness`.
16. `cached` lives here (BE-06 fallback flag). `Storm[]` is a bare array, so it has no flag.

**Storms / crops / rotations**
17. `Storm.antecedent_wetness` is a 0–1 fraction. `hyetograph.profile` is a free string.
18. `cover_curve` items are `[days_after_planting, cover_fraction 0–1]`. Season DOYs are 1–366, and `terminate < plant` means the crop overwinters.
19. `cover_calendar.monthly_cover` is one row per rotation year with **exactly 12** values (Jan–Dec). The PRD example's 3 values are a placeholder.
20. `/rotations/presets` returns exactly 3 items, existing first.

**Validate** (`POST /rotations/validate`)
21. The request is `{terrain_id, rotation{base_rotation_id?, name, sequence[]}}`. `terrain_id` is there for the season-window check.
22. The result is `{valid, warnings[{code, message, year?}], rotation?}`. Warning codes: `same_family_consecutive`, `outside_season_window`, `unknown_crop`. Only `unknown_crop` makes `valid=false`.
23. **New:** `rotation` returns the edited rotation with a stable hash ID `rot_custom_…` and a computed cover calendar. It can then go into `SimulationRequest.rotation_ids`. Without this, an edited rotation can't be simulated (FE-06 P1 swap → re-run).

**Scans**
24. `POST /scans` is multipart. `images` is a repeated part, **0–6 files** (JPEG/PNG/WEBP). It's optional because BE-02 has a no-upload fallback texture. The PRD's `images[]` is read as "array". `bbox` is a comma-separated string `minLon,minLat,maxLon,maxLat`. Response `202 {scan_id}`, also for an idempotent re-submit.
25. `ScanStatus` = `{status, stage, pct, terrain_id?, error?}`. `status` reuses `JobStatus` (queued|running|done|failed). `pct` is 0–100.
26. SSE: every message uses `event: progress`, including `ready` and `failed`. `ProgressEvent` carries an optional `terrain_id` (on ready) and an optional `error` (on failed).

**Simulations**
27. `SimulationRequest.rotation_ids`: 1–3 unique items. Options default to `grid_max 256, frames 60, soil_group B, soil_group_basis assumed`. `soil_group` is `A|B|C|D`.
28. `POST /simulations` returns `200` when cached and done, `202` when queued or running.
29. `SimulationStatus.progress` is a **0–1 fraction**, while scan `pct` is 0–100. Both match the PRD examples. `error?` is present on failure.
30. `results` is a map keyed by rotation ID. It only contains rotations that are **fully done**, so there are no partial results. `RotationResult` = `frames, risk, metrics, step_minutes, frame_times_min` (frame times in minutes from storm start). This is the §6.4 "companion JSON". It's renamed from `frame_times` to carry the unit.
31. Risk PNG: byte = relative index 0–100, `255` = masked.
32. `GET /simulations/{id}/evidence` returns `{evidence_cards: EvidenceCard[], insights: Insight[]}`.
33. **Diff (`?a&b`)** uses content negotiation on `Accept`. `image/png` gives a peak-water-depth diff `b − a`: `(byte−128)/127 * max_abs_diff_mm`, with 128 = no change. `application/json` gives `DiffStats {a, b, quantity:"peak_water_depth", unit:"mm", max_abs_diff_mm, mean_diff_mm, changed_area_ha (|diff|>1 mm), basis}`. This adds no endpoint and no query parameter.

**Insights / evidence / notes**
34. `Insight.severity` is an integer 1–5 (5 = most severe). `anchor.at_time_min` is nullable.
35. `EvidenceCard.support_not_replace` is a `const` of the exact PRD sentence.
36. Notes: `NoteCreate {terrain_id, anchor [lon,lat], body ≤2000, parent_id? (threads), author? ≤80}` and `Note` = NoteCreate + `id, created_at`. `GET /notes` returns `Note[]`, though the PRD table says `Note`. `POST` returns `201 Note`.

## Open questions (not encoded — need a team call)
- BE-08 "fall back to a lower grid size **with a flag**": no field for this yet. Should `SimulationStatus` get something like `downsampled: boolean`?
- BE-09 tips have `basis` and `verify_locally`, but `Insight.tip` is a plain string. Should `Insight` also get `tip_basis` / `verify_locally`?
- BE-06 "growing-season indicators" and seasonal series aren't modeled. They can be added as extra `TrendSeries` ids without a schema change.
- Upload size cap: not stated in the PRD. It's server config, signalled with `FILE_TOO_LARGE`.
