# Prompt 37 — NASA POWER client and cache (BE-06)

## Status
Core NASA POWER daily client implemented and pushed in commit `50b3be0`.
Prompt 37 remains partially complete; outstanding requirements are listed below.

## What was built
- NASA POWER daily point client using the official POWER API.
- Parameters: PRECTOTCORR, T2M, T2M_MAX, T2M_MIN, GWETROOT, GWETTOP.
- Latitude/longitude validation and date-range validation.
- Response validation, including rejection of non-finite measurements.
- Conversion of NASA POWER fill values to null (`None` in Python).
- Location/date-specific disk caching with coordinates rounded to three decimal places.
- Offline mode (`OFFLINE=1`) that never requests the network.
- Cached fallback when upstream requests fail.
- WEATHER_UNAVAILABLE (HTTP 503) when neither upstream nor cache is available.
- Best-effort cache writes: a disk-write failure does not discard valid upstream data.

## Known gaps
- Historical 1981-to-latest coverage has not been verified end to end.
- Request splitting for NASA POWER date-range limits has not been implemented.
- No dedicated opt-in live-network pytest test.
- Client returns validated dictionaries rather than the NumPy arrays or pandas DataFrame requested by Prompt 37.
- Cache is keyed by location and requested date range rather than one location-level file.
- Live weather is not yet wired into `/weather/storms` or `/weather/summary`.
- Source resolution, licensing, and provenance still require documentation and verification.
- `docs/progress/R1.md` and the required data-source research should be verified before final integration.
