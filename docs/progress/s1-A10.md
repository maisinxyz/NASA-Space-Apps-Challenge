## Local completion follow-up — 2026-11-12

- Fixed retry/context-loss recovery: every retry rebuilds terrain, rotation and diff assets; caches are scoped to simulation, tier, context and attempt. Retired requests cannot update the current viewer or surface stale load errors, and late textures are disposed. Completed rotations remain cached within the current scope for instant A/B swaps. Errors for a no-longer-visible rotation/pair do not interrupt the current selection.
- Fixed resource cleanup on unmount, retry, context loss and tier changes, including partially loaded terrain bundles and imagery arriving after another asset fails. Capability detection releases its temporary WebGL context. Fallback uses a labelled region so its retry button remains exposed to assistive technology.
- `/dev/viewer` measures time from the terrain metadata request through the first terrain draw via `onReady`. It labels that measurement separately from terraform completion, resets on terrain changes, and ignores out-of-order terrain/field requests.
- Public viewer API addition (agreed with the integrating owner): optional `ViewerStats.memory?: { geometries: number; textures: number; programs: number }`. These are measured three.js renderer resource **counts**, not memory bytes, available VRAM, or an estimated GPU memory footprint. The harness labels them accordingly. No HTTP contract or dependency changes.
